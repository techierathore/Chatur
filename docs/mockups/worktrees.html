Why a run gets its own copy
Every file a run changes stays in its own copy. Run #482 is editing Coverage.razor in ~/code/.chatur/wt/req-ui-118, not in the folder open in this window — so your own editing is never disturbed, and a half-finished run never leaves you with a file you did not write.
Each copy sits on its own branch. When the run is done you read its work on that branch, in the repository view, and take it across when you are happy with it.
Two runs never share a copy. If both are going, each has one of its own, and neither can see the other half-written.
